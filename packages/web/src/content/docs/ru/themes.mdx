С помощью opencode вы можете выбрать одну из нескольких встроенных тем, использовать тему, которая адаптируется к теме вашего терминала, или определить свою собственную тему.

По умолчанию opencode использует нашу собственную тему `opencode`.

---

## Требования к терминалу

Чтобы темы корректно отображались в полной цветовой палитре, ваш терминал должен поддерживать **truecolor** (24-битный цвет). Большинство современных терминалов поддерживают это по умолчанию, но вам может потребоваться включить его:

- **Проверьте поддержку**: запустите `echo $COLORTERM` — должен появиться `truecolor` или `24bit`.
- **Включить truecolor**: установите переменную среды `COLORTERM=truecolor` в профиле shell.
- **Совместимость терминала**: убедитесь, что ваш эмулятор терминала поддерживает 24-битный цвет (большинство современных терминалов, таких как iTerm2, Alacritty, Kitty, Windows Terminal и последние версии GNOME Terminal, поддерживают).

Без поддержки truecolor темы могут отображаться с пониженной точностью цветопередачи или вернуться к ближайшему приближению к 256 цветам.

## Системная тема

Тема `system` автоматически адаптируется к цветовой схеме вашего терминала. В отличие от традиционных тем, использующих фиксированные цвета, тема _system_:

- **Создает шкалу серого**: создает пользовательскую шкалу серого на основе цвета фона вашего терминала, обеспечивая оптимальный контраст.
- **Использует цвета ANSI**: использует стандартные цвета ANSI (0–15) для подсветки синтаксиса и элементов пользовательского интерфейса, которые соответствуют цветовой палитре вашего терминала.
- **Сохраняет настройки терминала по умолчанию**: использует `none` для цветов текста и фона, чтобы сохранить естественный вид вашего терминала.

Системная тема предназначена для пользователей, которые:

- Хотят, чтобы opencode соответствовал внешнему виду их терминала
- Используют пользовательские цветовые схемы терминала
- Предпочитают единообразный вид для всех терминальных приложений

## Использование темы

Вы можете выбрать тему, вызвав выбор темы с помощью команды `/theme`. Или вы можете указать её в файле `tui.json`.

```json title="tui.json" {3}
{
  "$schema": "https://opencode.ai/tui.json",
  "theme": "tokyonight"
}
```

## Пользовательские темы

opencode поддерживает гибкую систему тем на основе JSON, которая позволяет пользователям легко создавать и настраивать темы.

---

### Иерархия

Темы загружаются из нескольких каталогов в следующем порядке: более поздние каталоги переопределяют предыдущие:

1. **Встроенные темы** — они встроены в двоичный файл.
2. **Каталог конфигурации пользователя** — определяется в `~/.config/opencode/themes/*.json` или `$XDG_CONFIG_HOME/opencode/themes/*.json`.
3. **Корневой каталог проекта** — определено в `<project-root>/.opencode/themes/*.json`.
4. **Текущий рабочий каталог** — определено в `./.opencode/themes/*.json`.

Если несколько каталогов содержат тему с одинаковым именем, будет использоваться тема из каталога с более высоким приоритетом.

---

### Создание темы

Чтобы создать собственную тему, создайте файл JSON в одном из каталогов темы.

Для глобальных тем:

```bash no-frame
mkdir -p ~/.config/opencode/themes
vim ~/.config/opencode/themes/my-theme.json
```

Для тем проекта:

```bash no-frame
mkdir -p .opencode/themes
vim .opencode/themes/my-theme.json
```

---

### Формат темы

Файл темы — это объект JSON с тремя членами:

- **`$schema`** (необязательно) — указывает на `https://opencode.ai/theme.json` для автодополнения в редакторе. Носит информационный характер и никогда не влияет на поведение.
- **`defs`** (необязательно) — именованные цветовые константы, на которые можно ссылаться в остальной части файла.
- **`theme`** (обязательно) — сама тема: отображение **имён элементов** в записи стилей.

Элементы адресуются точечными именами, по одному на каждую отрисовываемую поверхность интерфейса. Каждая запись объявляет необязательный цвет переднего плана (`fg`), фона (`bg`) и набор текстовых `attributes`:

```json title="my-theme.json"
{
  "$schema": "https://opencode.ai/theme.json",
  "theme": {
    "dialog.title": {
      "fg": "#ffffff",
      "attributes": ["bold"]
    },
    "message.user.body": {
      "bg": "#1a1a2e"
    },
    "prompt.extmark.paste": {
      "fg": "message.user.body",
      "bg": "warning",
      "attributes": ["bold"]
    },
    "thinkingOpacity": 0.6
  }
}
```

Запись, в которой заданы не все каналы, является **частичным переопределением**: незаданные каналы сохраняют значения по умолчанию из каталога для данного элемента. Присутствующий массив `attributes` **заменяет** набор атрибутов элемента по умолчанию целиком — слияния не происходит. Чтобы убрать атрибут по умолчанию, перечислите только нужные атрибуты; чтобы убрать все атрибуты, используйте пустой массив.

#### Атрибуты

Массив `attributes` принимает ровно следующие значения:

`bold`, `dim`, `italic`, `underline`, `blink`, `inverse`, `hidden`, `strikethrough`

Каждое значение может встречаться в записи не более одного раза.

#### thinkingOpacity

`thinkingOpacity` — число от `0` до `1` (по умолчанию `0.6`), которое умножает цвет переднего плана каждого блока рассуждений, включая его заголовок, и альфу приглушенных цветов синтаксиса. Это скаляр внутри `theme`, а не часть записи элемента.

---

### Цветовые значения

Каждое значение `fg` и `bg` (и каждая константа `defs`) принимает:

- **Шестнадцатеричные цвета**: `"#ffffff"` с 3, 4, 6 или 8 цифрами — `"#f0f"`, `"#8015"`, `"#2eff6a"`, `"#00000096"` (последняя пара цифр — альфа-канал)
- **Цвета ANSI**: `3` (0–255) — разрешаются через фиксированную таблицу цветов, поэтому палитра терминала никогда не используется
- **Нет цвета**: `"none"` использует цвет терминала по умолчанию, `"transparent"` — полностью прозрачный
- **Ссылки**: имя, которое разрешается в другой цвет (см. ниже)
- **Темные/светлые варианты**: `{"dark": "#000000", "light": "#ffffff"}` — обязательны обе ветки, используется та, что соответствует активному режиму

#### Ссылки

**Безточечное** имя ссылки (буквы, цифры и подчеркивания, начинается с буквы) разрешается сначала против `defs` файла, затем против встроенной палитры. **Точечное** имя должно быть именем элемента из каталога и разрешается **по каналам**: ссылка в `fg` принимает разрешенный цвет переднего плана указанного элемента, ссылка в `bg` — его разрешенный цвет фона. Атрибуты через ссылку никогда не передаются.

```json
{
  "defs": {
    "ink": "#101010"
  },
  "theme": {
    "dialog.body": { "fg": "ink" },
    "dialog.title": { "fg": "dialog.body" },
    "prompt.text": { "bg": "dialog.title" }
  }
}
```

В теме v2 палитра содержит имена цветов встроенной темы по умолчанию — такие имена, как `primary`, `text`, `backgroundPanel`, `diffAdded` или `syntaxKeyword` (полный список см. в таблице ключей устаревшего формата). Именно поэтому частичная тема v2 работает без переопределения базовых цветов: всё, что вы не упомянули, откатывается к теме по умолчанию.

---

### Определения цвета

Раздел `defs` является необязательным и позволяет вам определять повторно используемые цвета, на которые можно ссылаться в теме. Запись `defs` содержит шестнадцатеричный цвет, индекс ANSI, `"none"`/`"transparent"` или ссылку на другую запись `defs`, имя палитры или элемент.

---

### Настройки терминала по умолчанию

Специальное значение `"none"` можно использовать для любого цвета, чтобы наследовать цвет терминала по умолчанию. Это особенно полезно для создания тем, которые органично сочетаются с цветовой схемой вашего терминала:

- `"dialog.body": { "fg": "none" }` — использует цвет переднего плана терминала по умолчанию.
- `"app.background": { "bg": "none" }` — использует цвет фона терминала по умолчанию.

### Ошибки

Файл темы, нарушающий формат, отклоняется при загрузке, и причина сообщается вам. Файл исключается из реестра тем, а активная тема откатывается к встроенной теме по умолчанию — отклоненный файл никогда не отрисовывается частично. Возможные причины:

| Причина                | Значение                                                                              |
| ---------------------- | -------------------------------------------------------------------------------------- |
| `PARSE_ERROR`          | Файл не является корректным JSON                                                        |
| `NOT_A_THEME`          | В файле нет объекта `theme`                                                             |
| `MIXED_FORMATS`        | Записи элементов v2 и ключи цветов v1 смешаны в одном объекте `theme` — используйте один формат на файл |
| `UNKNOWN_ELEMENT`      | Имя элемента отсутствует в каталоге (каталог закрыт)                                     |
| `UNKNOWN_ATTRIBUTE`    | Массив `attributes` содержит значение вне восьми известных атрибутов                     |
| `INVALID_COLOR`        | Некорректный hex, индекс ANSI вне 0–255 или значение, не являющееся цветом               |
| `UNRESOLVED_REFERENCE` | Имя ссылки не найдено ни в `defs`, ни в палитре, ни в каталоге                           |
| `CYCLIC_REFERENCE`     | Цепочка ссылок повторно посещает имя                                                     |
| `INVALID_ENTRY`        | Запись элемента содержит член вне `fg`/`bg`/`attributes` либо `attributes` не является массивом |

Обратите внимание: опубликованная [JSON-схема](https://opencode.ai/theme.json) по-прежнему считает корректным файл, смешивающий оба формата, чтобы редакторы продолжали предлагать автодополнение для устаревших файлов, — сам opencode строже и отклоняет смесь с ошибкой `MIXED_FORMATS`.

### Устаревший формат (v1)

Раньше темы представляли собой плоское отображение ключей цветов в camelCase. Такие файлы всё ещё загружаются: при загрузке они **автоматически мигрируют** в формат элементов, и миграция не имеет потерь — каждая поверхность отрисовывается ровно теми цветами, которые отрисовывала раньше. Смешивание ключей v1 с записями элементов в одном файле отклоняется (`MIXED_FORMATS`), поэтому новые темы следует создавать исключительно в формате элементов.

```json title="legacy-theme.json"
{
  "$schema": "https://opencode.ai/theme.json",
  "theme": {
    "primary": { "dark": "#88C0D0", "light": "#5E81AC" },
    "background": { "dark": "#2E3440", "light": "#ECEFF4" }
  }
}
```

Файл v1, задающий лишь часть ключей, тоже допустим: отсутствующие имена палитры откатываются к встроенной теме по умолчанию. Шесть ключей, которые никогда не достигали отрисовываемой поверхности (`diffHunkHeader`, `markdownHorizontalRule`, `markdownListEnumeration`, `markdownImage`, `markdownImageText`, `markdownCodeBlock`), при миграции игнорируются.

### Каталог элементов

Каталог ниже перечисляет все адресуемые элементы — это закрытый набор, и тема, называющая элемент вне его, отклоняется с ошибкой `UNKNOWN_ELEMENT`. Столбцы — значения по умолчанию для каждого канала:

Run-zone derivatives stay computed and carry no elements: the footer
`status`, `statusAccent`, `shade`, `surface`, and `line` fields are
tui-theme/tint or tui-theme/fade derivations of `run.footer.pane`,
splash `leftShadow`/`rightShadow` fields are tui-theme/tint derivations of
the splash colors with `splash-shadow-alpha`. The run block diff fields
(`diffAdded`, `diffRemoved`, `diffAddedBg`, `diffRemovedBg`, `diffContextBg`,
`diffHighlightAdded`, `diffHighlightRemoved`, `diffLineNumber`,
`diffAddedLineNumberBg`, `diffRemovedLineNumberBg`) resolve from the
`run.block.diff.*` elements above, whose defaults equal the palette diff names
they replace. Because these surfaces are now element-addressable, a theme can
restyle the run diff per channel - for example, clearing the added-line
background entirely with:

```json
{
  "theme": {
    "run.block.diff.added-bg": { "bg": "transparent" }
  }
}
```
