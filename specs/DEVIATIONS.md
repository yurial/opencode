# Specification Deviations

- D1. `2026-10-29`, tool-task
  - Spec edit: durable task-run registry with status and continue surfaces — a `task_id` call without a prompt returns a status snapshot, a `task_id` call with a prompt extends a live run or continues the durable subagent session, the `task_run` table records launch, settle, and cancel with a derived interrupted reading, and the read-only `task_status` tool plus the `session.task.list`, `session.task.get`, and `session.task.continue` endpoints expose the registry.
  - Was: the task tool requires `prompt` on every call; a `task_id` call against a run with no live job starts a new background run of the same session and returns a running result, and no status-only path exists; run state lives in process memory only and disappears on restart; no `task_status` tool and no `session.task.*` endpoints exist.
  - Now: the spec requires the durable `task_run` registry with writes at launch, settle, and cancel, restart survival, and the derived interrupted reading without mutation; the status-only call, the `task_status` tool, and the three HTTP endpoints are mandatory surfaces; a continuation admits the prompt into the same durable subagent session.
  - Code impact: `packages/opencode/src/tool/task.ts` (status path, continuation branch, registry writes), a new `task_run` table in the `packages/core` schema with a generated migration, a new `task_status` built-in registration, `server.session` protocol group endpoints with a server handler and a `TaskNotFoundError` public error, client and legacy SDK regeneration.
  - Tests: none yet — spec-first change; the Tests section of tool-task defines the required coverage.
  - Review focus: registry write points at launch, settle, and cancel; the continuation branch reusing the ordinary prompt admission of the subagent session; the derived interrupted read mutating nothing; read-only-ness of the status endpoints; wire-schema regeneration after adding the endpoints.
